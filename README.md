# 最后的分子 · LastMolecule

Godot 4 药物研发策略卡牌游戏（v0.4）。玩家经营一家小药企，用一个个候选药物项目积累研究证据，最终重启公司搁置多年的分子 LM-001「最后的分子」。每个项目都要管理资金、研发年份、疗效和安全风险，从候选化合物发现推进至获批上市。

## 启动

使用 Godot 4.7 或更高版本导入 `project.godot`，按 F5 从标题界面（`title.tscn`）启动；按 F6 运行 `main.tscn` 可直接开一局。当前验证环境为 Godot 4.7.1，默认窗口为 1280×720。

macOS 命令行启动：

```sh
/Applications/Godot.app/Contents/MacOS/Godot --path .
```

## 玩法

一局对应一个候选药物项目：五个研发阶段（候选化合物发现 → 临床前 → 一期 → 二期 → 三期），通过上市审评即为成功。设计说明见 `docs/superpowers/specs/2026-10-25-core-gameplay-design.md`。

战斗参照杀戮尖塔：项目指标直接映射成战斗属性——**安全风险就是血量**（玩家生命 = 100 − 安全风险，挨打会直接涨安全风险，到 100 项目被叫停），**疗效换算成开局效力**（每超过 20 点 +1 伤害），**数据决定 AI 卡档位**。

- **分支地图**：每个阶段 5 层节点 + Boss + 里程碑。第一层是实验难题（普通战斗），最后一层是平台建设（休整）。节点类型：实验难题、关键难关（精英，奖励研发能力）、研究（三选一方案 + 选卡，前期研究最多削弱 Boss 30% 生命）、事件、合作融资（注资/买卡/删卡）、平台建设（安全评估 −25 风险 / 升级卡 / 梳理流程）、加速通道（后续节点不耗时，Boss 生命 +15%）。地图右侧始终预告本阶段 Boss。
- **时间**：每个节点消耗 2–6 个月，满一年扣 2 亿年度成本，竞品随之推进。
- **战斗**：每回合 3 点行动力、抽 5 张牌；敌人头顶显示下回合意图；防护在自己回合开始时清零。状态有靶点暴露（易伤）、药效抑制（虚弱）、效力、规范、持续损伤（中毒）、代谢稳定、反噬、疾病进展等。
- **五个阶段 Boss**：活性悬崖（一回合超过 3 张攻击牌会反噬）、毒性风暴（叠持续损伤 + 每 3 回合重击）、剂量限制性毒性（可加剂量，双方一起变强，锁定剂量带进二期）、疾病进展（逐回合变强并塞入「不良反应」牌）、多中心三期试验（三个中心同时作战，没被攻击的中心获得防护）。
- **卡牌**：分子设计（输出）、实验验证（防护与数据）、临床策略（持续损伤、抽牌、行动力）、AI 技术（数值最高，受数据档位影响，可能偏差并塞入噪声数据）、流程建设（整场生效的能力牌）。卡面数值实时计入效力与靶点暴露。
- **研发团队等级**：打赢战斗得经验（普通 1 / 精英 2 / Boss 3），升到 Lv5。每级烧瓶都会进化（小烧瓶 → 锥形瓶 → 反应装置 → 自动化工作站 → 智能实验室），并自带开场护盾、力量、第一回合多抽、坚固等小能力（`data/player.json`）；主要战力仍来自卡牌。
- **奖励**：普通战斗选卡（可跳过）；精英额外选研发能力；Boss 疗效 +12、安全风险 −25，并选卡和能力，然后进入里程碑。
- **竞争格局**：竞品获批会抬高终审疗效门槛、让之后的 Boss 更强；竞品读出或新机制出现会让融资变难。
- **里程碑 Go/No-Go**：继续 / 主动终止。主动终止回收 60% 数据和部分资金到公司；失败只回收 30%。
- **跨局积累**：公司数据与流程等级保存在 `user://company.json`，提升 AI 起步能力并解锁新 AI 卡与能力。
- **局内存档**：地图、事件、选卡、奖励时自动存档（`user://run.json`），标题界面可「继续项目」；战斗中退出会从那场战斗开头重打。

### 项目类型与主线（`data/projects.json`）

- **立项选择**：标准新药（★，无额外规则）、高选择性（★★，发现与临床前一回合第 3 张攻击牌起脱靶反噬，攻击带破绽的目标不算）、长期安全性（★★，每进入新阶段残留风险 +5，一期起敌人每 2 回合力量 +1）。特色项目在里程碑有一次三选一的专属决策，效果持续到项目结束。
- **项目编号**：普通项目从 LM-002 起递增，LM-001 留给主线最终项目。
- **研究证据**：项目获批，或在一期及以后的里程碑主动终止，获得该类项目的证据（同类只记首次）。集齐 2 项解锁 LM-001。
- **LM-001「最后的分子」**（★★★）：开局按已有证据选研究路线（常规 / 提高选择性 / 提高稳定性，各有代价），前期有选择性规则、后期有敌人成长，三期是专属最终 Boss。获批按路线进入三种主线结局之一，一期之后主动终止进入「把答案留下」；结局页列出因果链（哪个项目带来哪项证据、做过什么决策、选了哪条路线）。

### 构筑与阶段差异（v0.4）

- **套路**：分子快攻（力量 + 多段）、毒性控制（中毒 + 引爆）、稳健防守（护盾 + 反证实验 / 重复验证 / 稳定平台 / 安全药理学网络）、数据驱动（AI 先导优化随本场数据变强、AI 训练平台放大数据；依赖公司数据积累，适合中后期）、流程体系、临床节奏。查看牌库时显示牌组构成与当前套路。
- **阶段卡池**（`cards.json` 的 `stage_type_bias`）：发现多分子设计与 AI，临床前多实验验证，一期多实验与流程，二期多临床策略与 AI，三期多流程与临床。
- **阶段地图**（`maps.json` 的 `stage_weights`）：发现偏探索（研究、事件多），临床前偏排雷（战斗、精英多），一期偏生存（平台休整多），二期偏疗效验证（研究、精英多），三期偏多中心管理（事件、合作多）。

## 界面、美术与音乐

- **页面**：标题界面（开始新项目 / 公司档案 / 玩法说明 / 设置 / 制作名单 / 退出）→ 研发主界面 → 地图、事件、阶段试验等弹窗 → 结局画面（再来一局 / 返回标题）。游戏中按 Esc 或点右上角「菜单」可打开游戏菜单。
- **标题主视觉**（`TitleHero`）：搁置多年的 LM-001 悬浮在光柱底座上，烧瓶团队站在一旁；随主线进度变化（搁置中偏红 → 证据集齐转金 → 主线完成转绿），烧瓶随公司获批数进化。
- **研发总览**（`HubView`）：实验室场景——烧瓶站在实验台上，候选分子悬浮在分析仪上方，灯光随阶段变色；左上 RPG 式状态栏（生命、资金、年份、疗效、前期研究），右侧 AI / 研发能力 / 竞争格局为可展开卡片（`InfoCard`），实验台正面是团队铭牌、消息与主按钮。
- **研发地图**（`MapCanvas` / `MapNode`）：从左往右推进的六边形路线图，走过的路是绿线，可走的路是流动的金色虚线，当前位置有小烧瓶标记；右侧常驻 Boss 预告，其余收进可展开卡片。
- **事件与里程碑**：选项是卡片——图标徽章、标题与说明、效果小标签（收益绿、代价红、耗时金），条件不满足时变暗并标明缺什么。
- **设置**：主音量、音乐、音效、全屏、语言（中文 / English），保存在 `user://settings.cfg`；标题界面的设置页可以重置公司档案。
- **美术**：`assets/icons/*.svg` 手写线性图标；`assets/theme/main_theme.tres` 全局主题；动态分子背景、管线进度条、分子插画都是代码绘制（`scripts/ui/`）。中文字体按顺序使用系统里的冬青黑体（Hiragino Sans GB）、微软雅黑、Noto Sans CJK SC。不用「PingFang SC」，因为 Godot 在 macOS 上会把它匹配到缺简体字的 PingFang HK。
- **卡牌**：名称条按角色上色（红攻击、蓝护盾、绿技能、金能力、灰坏牌），名称过长自动缩字或换行；效果用「图标 + 大号数字 + 两三个字」逐行显示，实时数值变高显示绿色、变低显示红色；限制与 AI 失误率紧跟效果；类型、角色、稀有度和 AI 倍率是插画上的小标记。战斗手牌尺寸下所有文字不小于 12px。右键或长按任意卡打开大图与完整说明（`CardDetail`）。文案保留专业术语并配白话说明。
- **生命值**：生命 = 100 − 安全风险，研发地图底栏和总览都显示；普通战斗不回血，回血靠阶段 Boss、平台建设、部分事件与能力。
- **氛围**：玩家血条是绿色带爱心，脚下绿色光圈；敌人血条红色。生命低于 30% 时屏幕边缘泛红闪烁并有心跳声；Boss 战常驻暗红压迫边框，Boss 和精英出招有踏地声和震屏，高伤害意图会放大闪烁。
- **战斗画面**：敌人和 Boss 都是代码绘制的生物（细胞、团块、尖刺、晶体、毒云五种形态，会呼吸、眨眼、受击闪白、死亡消散），玩家是一只液面随血量变化的烧瓶。出牌有飞行动画，受击有伤害数字、粒子和震屏，敌人出招会前冲；Boss 登场有横幅和专属音乐。单体牌在多个敌人时点卡后再点目标；快捷键 E 结束回合、1–9 选牌，右键或 Esc 取消选目标。
- **LM-001 主题**：`tools/gen_audio.py` 里一段固定编排的 8 小节旋律（`THEME`），在标题（缓慢电钢琴）、最终 Boss 战（`boss_final`，钟声与拨弦齐奏）和主线结局（获批为大调完整版 `campaign_approved`，「把答案留下」为单音版 `campaign_archive`）中反复出现；研发日常的旋律也改为编排好的乐句。只改音乐时运行 `tools/gen_audio.py --music-only`，音效保持不变。
- **烧瓶表情**：平时眨眼；受击「> <」后缩；打赢跳起来笑；生命低于 30% 担心冒汗；选目标时专注；失败垂头流泪。
- **最终 Boss 造型**：LM-001 本身——与标题页同一颗多环分子，核心里有脸、外圈金色光环；受伤时外圈原子逐个熄灭，半血后转快并泛红。
- **音乐与音效**：`assets/audio/` 下的 ogg 由 `tools/gen_audio.py` 程序合成（需要 numpy 和 ffmpeg），包括四段循环背景乐（标题 / 研发日常 / 战斗 / Boss）、胜负与三种结局短乐句，以及约 30 个音效（攻击挥击、AI 电流、分层命中与重击、烧瓶受击、金属护盾、心跳、Boss 咆哮与踏步、升级等）。改动后重新生成：

```sh
/usr/bin/python3 tools/gen_audio.py
```

## 代码结构

| 路径 | 职责 |
| --- | --- |
| `scripts/game.gd` | 回合状态机、节点分发、事件与选卡结算、奖励、里程碑与终局 |
| `scripts/project_state.gd` | 项目属性（疗效、安全风险、进度、资金、年份、本局数据）与效果结算 |
| `scripts/research_map.gd` | 分层分支地图生成与游标 |
| `scripts/battle_manager.gd` | 战斗核心：牌堆、行动力、伤害与状态结算、敌人回合、Boss 机制、AI 档位与偏差；每次操作输出事件列表供界面播放 |
| `scripts/combat/combatant.gd`、`enemy.gd` | 战斗单位（生命、防护、状态）与敌人出招模式 |
| `scripts/ui/battle/*.gd` | 战斗画面、敌人组件、血条、状态栏 |
| `scripts/ui/creature_view.gd`、`player_avatar.gd`、`card_face.gd`、`player_hud.gd` | 敌人形象、会进化的玩家烧瓶、牌面、主界面团队卡片的程序绘制 |
| `scripts/competition.gd`、`scripts/company.gd` | 竞品格局；公司资产、研究证据、主线进度与跨局存档 |
| `scripts/core/project_types.gd`、`run_save.gd` | 项目类型配置合并与编号；局内存档 |
| `scripts/rd_ui.gd` 及各 `*_popup.gd`、`map_screen.gd`、`map_canvas.gd`、`card_view.gd` | 研发主界面与弹窗 |
| `scripts/screens/title_screen.gd`、`scripts/ui/*.gd` | 标题界面、设置 / 玩法说明 / 公司档案 / 菜单 / 结局等页面，背景与插画绘制，`UIKit` 通用控件 |
| `scripts/core/game_audio.gd`、`scene_router.gd`、`game_settings.gd` | 音乐音效（自动加载 `Sound`）、场景淡入淡出（自动加载 `Router`）、玩家设置 |
| `data/*.json` | 项目、项目类型（`projects.json`）、卡牌、敌人、遭遇与奖励、能力、地图、研究方案、事件、竞品、公司配置 |
| `localization/translations.csv` | 中文与英文文案源文件 |

业务层通过信号通知界面，界面将玩家操作转发给业务层。新增内容优先修改 JSON 和翻译表。

## 验证

首次检出或修改翻译后先执行资源导入，再运行回归检查。`tests/run.sh` 会把脚本运行时错误也当作失败（这类错误会让某个测试函数中途退出、跳过后续检查）：

```sh
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --editor --import --quit
tests/run.sh
```

包含一条完整主线回归：两类项目获批得证据 → 解锁 LM-001 → 选路线 → 二期决策 → 补数据 → 获批 → 重开再通关。

平衡模拟（规则型机器人跑 N 局，战斗洗牌使用局内种子，结果可复现）：

```sh
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --script tests/run_tests.gd -- --sim=300 [--type=selective] [--build=poison] [--company-data=220] [--decision=1] [--naive=1]
```

输出结局、各阶段胜率、按牌组主导套路的获批率、每张卡在终局牌组里的获批率。参数：`--type` 项目类型；`--build` 机器人偏向的套路（molecular / experiment / clinical / ai / process / poison）；`--company-data` 模拟公司已积累的数据；`--decision` 里程碑专属决策选第几项；`--naive=1` 无视项目规则一味猛攻。

v0.4 数值下（300 局，新公司 / 公司数据 220）：不挑牌约 38% / 60%；分子快攻 55% / 61%，稳健防守 35% / 57%，临床 38% / 52%，毒性控制 39% / 66%，流程 40% / 61%，数据驱动 7% / 62%（AI 依赖公司积累，属于中后期套路）。项目类型：标准约 40%，高选择性约 36%，长期安全性约 24–27%，LM-001 约 29%。
