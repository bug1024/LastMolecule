# 核心玩法改造设计（P0）

日期：2026-10-25
状态：待确认

## 1. 意图

现有原型跑通了"地图 → 选牌 → 事件 → 战斗 → 奖励 → 评审"的流程，但玩家的选择几乎不影响结果：研发进度没有用处，卡牌只是加属性，地图是直线，全局只有一场"降风险条"的战斗。

这次改造要让玩家体验到真实药物研发中的取舍：

- **快 vs 疗效 vs 安全**：加快进展，同时尽量少出现疾病进展（PD）和不良反应（AE）。三者互相拉扯。
- **继续还是停（Go/No-Go）**：最关键的决策往往由外部变化触发，比如竞品领先、出现更合适的新机制，而不是项目本身做得好不好。
- **AI 的价值取决于积累**：有数据沉淀和流程梳理时，AI 作用很大；没有时，AI 不可靠。

**成功的定义**：药物通过审评、获批上市。

## 2. 受众与术语

- 面向**懂一些药物研发**的玩家，但入门门槛要低。
- 术语以中文为主，缩写作补充，例如"不良反应（AE）""疾病进展（PD）""剂量限制性毒性（DLT）"。
- 较专业的概念在悬停提示中附一句中文说明。
- 规则和数值简化、直观，不追求法规级真实。目标是让懂行的人会心一笑，而不是做模拟器。

## 3. 目标、非目标、反目标

**目标**
- 每个属性都有明确用途，影响后续决策。
- 五个阶段各有一套战斗规则；共用一套出牌操作。
- 前一阶段的结果影响后续阶段（跨阶段联动）。
- 卡牌类型有机制差异；AI 卡由"数据 + 流程"驱动。
- 竞争格局随时间推进，并改变审评门槛和融资环境。
- 每个里程碑都是 Go/No-Go 决策点，主动停项目是合理策略。
- 分支地图：选的是"怎么推进"，不是"走不走"。
- 跨局积累公司数据与流程等级。

**非目标（P0 不做）**
- 美术、音频、动效打磨（属于 P1/P2）。P0 的 UI 以"能玩、信息清楚"为准。
- 局内中途存档（只做跨局的公司存档）。
- 多种药物类型与适应症的完整内容（只保留扩展口子，见第 11 节）。
- 市场价值或收益打分。

**反目标（出现了就算失败，即使功能都实现了）**
- 卡牌仍然是"挑数值最大的那张"，没有取舍。
- AI 卡从第一局起就是万能最优解。
- 跨局积累让后续对局无脑通关。
- 满屏缩写，不懂行的玩家看不懂。
- 五种战斗只是换皮，打法实际相同。

## 4. 约束

- Godot 4.7，GDScript，GL Compatibility 渲染，1280×720。
- 保持现有架构：业务层（`game.gd`、`project_state.gd`、`battle_manager.gd` 等）无 UI 依赖，通过信号与 UI 通信。
- **数据驱动**：卡牌、战斗、地图、事件、竞品、数值全部放在 `data/*.json`，不写死在脚本里。
- 所有文案走 `localization/translations.csv`（中文为主，英文可后补）。
- 现有回归测试 `tests/run_tests.gd` 需要随改造更新，并保持"固定种子可通关"的测试。

## 5. 属性体系

| 属性 | 层级 | 来源 | 作用 |
|---|---|---|---|
| 疗效 | 本局 | 原「成功率」更名；分子卡、战斗结果 | 二、三期战斗的基础值；最终审评硬门槛 |
| 安全风险（AE 风险） | 本局 | 原「安全风险」；部分卡和事件会提高它 | 提高战斗中 AE 的出现频率和一期 DLT 概率；达到 100 时项目被监管叫停（失败） |
| 研发进度 | 本局，每阶段清零 | 研究节点、事件 | 阶段战斗的入场门槛（见 6.1） |
| 资金 | 本局 | 初始资金、融资、合作 | 年度消耗、节点费用；归零即失败 |
| 年份 | 本局 | 每个节点 +1 | 驱动竞品推进 |
| 本局数据 | 本局 | 实验卡、临床卡、战斗、研究节点 | AI 卡威力来源；局末按比例存入公司数据 |
| 公司数据 | 跨局 | 每局结算 | AI 卡的"起步底子"；累计到阈值会提升流程等级 |
| 流程等级 | 跨局（0–5） | 公司数据累计解锁；本局"流程卡"可临时加成 | 决定数据利用率；解锁新 AI 卡进入卡池 |

"能力"（原 abilities）改为**持续触发的研发能力**，类似遗物。例如："每打出 3 张实验卡，本局数据 +2"。不再是一次性加属性。

**能力来源**（我的决定）：只有一套能力系统。能力仍然来自阶段战斗胜利后的奖励（一张卡加一项能力，各从候选中选一），也可以在合作/融资节点购买。流程等级提升会把新能力加入候选池，这就是第 10 节说的"流程能力"，与这里是同一个系统。能力只在本局有效，不写入存档。

### 5.1 疗效的累积方式（我的决定）

疗效在整局中**累加**，不会被某个阶段直接覆盖。各阶段的贡献规模不同，越靠后权重越大：
- 初始疗效（项目档案给定，初值 20）
- 发现期：活性换算加成，0 到 +10
- 一期：不直接加疗效，而是通过推荐剂量影响二期的基础值
- 二期：有效人数换算，−5 到 +25
- 三期：PD 压力换算，−10 到 +15
- 研究节点和事件：零散加成

这样每个阶段都影响终审，但二、三期最关键。这与现实一致。各项区间都是初值，由平衡测试调整。安全风险采用同样的累加方式。

## 6. 一局的结构

```
立项 → [阶段 1 地图 → 阶段战斗 → 里程碑 Go/No-Go] → … → 阶段 5 → 上市审评 → 获批（成功）
```

五个阶段：候选化合物发现 → 临床前研究 → 一期临床 → 二期临床 → 三期临床。

### 6.1 分支地图

- 每个阶段一张小型分层地图：3 层可选节点，每层 2–3 个，相邻层之间有连线。最后汇聚到**阶段战斗**节点，然后是**里程碑**。
- 地图由每个阶段的 JSON 模板生成（节点类型权重、层数、连线规则），每局不同。
- 每进入一个节点，年份 +1，扣年度成本。现有规则保留。

**节点类型**

| 节点 | 作用 |
|---|---|
| 研究 | 三种推进方案三选一，体现"快 / 稳 / 省"取舍，例如"加班并行推进：进度 +12，资金 −3，安全风险 +4"。同时可从 3 张候选卡中选 1 张加入牌库，也可以跳过。这里的卡只是"获得"，不会打出 |
| 事件 | 随机事件（含竞品相关事件） |
| 合作 / 融资 | 类似商店：用资金买卡、删卡；或接受合作伙伴注资，代价是"分担部分研发进度"之类的条件 |
| 平台建设 | 类似休整点：删一张卡、升级一张卡，或本局流程临时 +1（三选一） |
| 加速通道 | 路线标签：本阶段年份消耗减少，但本阶段战斗的胜利门槛提高 |

**进度门槛**（我的决定）：每个阶段只有一个门槛，即进入阶段战斗所需的进度（初值 30）。战斗胜利不再加进度。
- 地图生成时要保证：任意一条路线经过的研究节点和事件，期望进度都能达到门槛。
- 如果到达战斗节点时进度仍不足，战斗节点提供"补充研究"：花 1 年和少量资金，进度 +10，可以重复。这样不会卡死，只会更慢、更贵。

**"怎么推"的路线取舍**通过节点组合体现：走加速通道（快，门槛高）、走合作（省钱，代价是条件）、走研究 / 平台（慢，但数据和牌库扎实）。

### 6.2 里程碑：Go/No-Go

每个阶段战斗结束后进入里程碑，玩家能看到：当前属性、竞品状态、下一阶段预计门槛。

选项：
- **继续**：进入下一阶段（需要战斗胜利）。
- **重做本阶段**：战斗失败或指标不理想时可选。重新生成本阶段地图，花更多年份和资金。
- **主动终止**：本局结束，不算失败。本局数据按**较高比例**（初值 60%）存入公司数据，剩余资金的一部分（初值 30%，有上限）转为下一局的开局资金加成。

被动失败（资金归零、安全风险 100、终审未通过）时，本局数据按较低比例（初值 30%）存入公司数据。

### 6.3 上市审评

三期胜利后进入终审。判定为确定性门槛（**我的决定**，不做概率判定）：
- 疗效 ≥ 疗效门槛（初值 60，竞品事件会提高它）
- 安全风险 < 安全门槛（初值 70）

满足即获批上市，本局成功。不满足时可以追加研究（花钱时间提升疗效），或终止。

## 7. 竞争格局

- 每局生成 2–3 条**竞品管线**，各自有当前阶段和每年推进概率（来自 `data/competitors.json`）。
- 在地图界面的侧栏显示竞品进度。
- 随年份推进，竞品会前进、读出数据、失败或获批。另有"新机制论文发表"类全局事件。

**对玩家的影响**

| 外部事件 | 影响 |
|---|---|
| 竞品获批上市 | 标准治疗改变：终审疗效门槛 +10（初值），二、三期战斗的有效门槛也相应提高 |
| 竞品读出积极数据 | 融资类节点的收益下降 |
| 新机制出现 | 疗效门槛 +5，融资收益下降 |
| 竞品失败 | 门槛不变，融资收益上升 |

这样"该不该停"的判断依据很清楚：门槛已经高到够不着，或者钱撑不到终点。

## 8. 战斗系统

### 8.1 共用底层

- 行动力、手牌、抽牌堆、弃牌堆、结束回合，沿用现有逻辑。
- **意图预告**：每回合开始时，显示本回合结束时将发生的威胁，玩家可以针对性应对。
- **统一的卡牌效果词汇**：卡牌的战斗效果用一组通用动词描述，由各阶段的战斗规则自行解释。这样同一张卡在不同阶段有不同作用，但卡牌数据只写一次。

| 动词 | 含义 |
|---|---|
| 疗效 +X | 推动"有效"方向的指标 |
| 安全 +X | 抵消 AE、毒性类威胁 |
| 推进 +X | 推进入组、实验进度 |
| 抽牌 N | 抽 N 张 |
| 洞察 N | 预知未来 N 回合的意图，或揭示隐藏的随机结果 |
| 数据 +X | 本局数据增加 |
| 防护 X | 本回合抵消 X 点即将到来的威胁（类似格挡） |

每种战斗规则在 UI 中说明每个动词在本阶段的作用。

### 8.2 各阶段规则（数值均为初值，待平衡）

**阶段 1 · 候选化合物发现：分子优化（配平）**
- 三条指标：活性、选择性、成药性，各 0–100，目标区间 60–80。另有一条"毒性"指标。
- 动词映射：疗效 → 活性，安全 → 选择性（同时降低毒性），推进 → 成药性。部分分子卡会顺带提高毒性。
- 超出区间上限会扣分（模拟"顾此失彼"），所以要配平，不是越多越好。
- 6 回合内三条都进入区间即胜利。毒性达到 100 即失败。
- **联动**：最终活性转化为疗效初值加成；最终毒性转化为安全风险加成。

**阶段 2 · 临床前：毒理挑战**
- 沿用现有风险条（初始 80，降到 0 胜利，升到 100 失败）。
- 意图从意图池中抽取，例如"毒性信号：风险 +12""器官毒性：风险 +20""结果延迟：下回合行动力 −1"。
- 安全 → 降低风险；防护 → 抵挡本回合意图；疗效在此阶段无效。
- **联动**：剩余回合数换算成节省的年份；最终风险值影响安全风险。

**阶段 3 · 一期：剂量爬坡（见好就收）**
- 剂量档位 1–6。每回合出牌后，玩家选择"加一档剂量"或"维持"。
- 回合结束时进行 DLT 判定，基础概率随剂量递增（初值：0/5/10/20/35/50%），再加上安全风险修正，并被本回合打出的"安全"点数降低。
- 同一剂量出现 2 次 DLT：退回上一档，并自动锁定为推荐剂量。在 1 档出现 DLT 即失败。
- 测试过至少 2 个剂量档后，可随时点击"确定推荐剂量"结束战斗。
- 推进 → 本回合可以连加两档；洞察 → 提前看到本回合的 DLT 判定结果。
- **联动**：推荐剂量越高，二期的疗效基础值越高，但二期 AE 出现率也越高。

**阶段 4 · 二期：疗效信号**
- 12 名受试者，状态为：治疗中 / 有效 / 疾病进展（PD）/ 因 AE 脱落。
- 意图：每回合标出几名将要出现 PD 或 AE 的受试者（数量由疗效基础值、AE 率、推荐剂量决定）。
- 疗效 → 消除 PD 标记，或推动"治疗中 → 有效"；安全 → 消除 AE 标记；推进 → 补入新受试者（替换脱落者，有上限）。
- 5 回合后，有效人数 ≥ 门槛（初值 5/12，竞品获批后提高）即胜利。
- **联动**：有效人数转化为疗效；AE 脱落数转化为安全风险。

**阶段 5 · 三期：多中心稳住（多线兼顾）**
- 四条轨道：入组进度（目标 100）、PD 压力、AE 压力、脱落率（各 0–100）。
- 意图：每回合各条压力轨道上涨，幅度不同，并随机出现"某中心入组停滞""安全性信号"等。
- 推进 → 入组；疗效 → PD 压力；安全 → AE 压力；临床卡特有效果 → 脱落率。
- 8 回合内入组达到 100 即胜利；任一压力轨道达到 100 即失败。
- **联动**：结束时的各压力值修正最终的疗效与安全风险，进入终审。

**战斗失败**：不直接结束本局，进入里程碑，玩家选择"重做本阶段"或"主动终止"。

## 9. 卡牌体系

### 9.1 四种类型的固定定位

| 类型 | 定位 | 特点 |
|---|---|---|
| 分子 | 疗效 | 部分卡有毒性、安全风险的副作用 |
| 实验 | 安全、数据 | 主要的数据来源之一；防护类效果 |
| 临床 | 推进、速度 | 主要的数据来源之一；部分卡提高 AE 或安全风险 |
| AI | 抽牌、洞察、放大 | 威力取决于有效数据（见 9.2） |
| 流程（新增，少量） | 本局流程临时加成 | 不直接作战，用来"搭基础设施" |

每张卡至少有一个取舍：费用、副作用、风险概率，或依赖条件。不出现纯加数值的卡。

**卡牌只在战斗中打出**（我的决定）。这是对现有设计的改动：现在普通节点会从已有卡里抽 3 张、付资金打出一张。改造后，卡牌数据中的 `effects`、`cost`（资金费用）、`risk` 字段删除，只保留战斗相关字段。地图层的推进由研究节点的方案选择承担。

- 资金只花在节点和年度成本上，战斗中只消耗行动力。
- "数据 +X"在战斗中打出时生效，计入本局数据。
- 需要影响地图层的卡（如"AI 竞品情报"）也在战斗中打出，效果在战斗结束后生效。例如揭示下一个竞品事件，显示在地图侧栏上。

### 9.2 AI 卡：数据与流程驱动

**有效数据** = (本局数据 + 公司数据 × 迁移率) × 数据利用率

- 迁移率：同类项目 100%，不同适应症 50%（P0 只有一类项目，先保留字段）。
- 数据利用率：由流程等级决定（初值：0 级 40%，每级 +12%，5 级 100%）。本局流程卡可临时加成。
- 公司数据的贡献设上限（初值：最多提供"中档"所需的有效数据），保证本局数据仍是主力。

**有效数据分档**（初值）

| 档位 | 有效数据 | AI 卡效果倍率 | 模型偏差概率 |
|---|---|---|---|
| 低 | < 20 | ×0.5 | 30% |
| 中 | 20–60 | ×1 | 15% |
| 高 | > 60 | ×1.75 | 5% |

**模型偏差**：AI 卡的效果作废，并触发该卡定义的小副作用。例如"洞察"显示了错误的意图，或预测错误导致资源浪费。

UI 必须显示当前有效数据、档位和偏差概率，让玩家理解"为什么 AI 现在不靠谱"。

**AI 卡示例**（首批 8–10 张，具体数值留给开发者平衡）
- AI 虚拟筛选：疗效 +X，抽 1。
- AI 毒性预测：洞察 2（看到未来 2 回合的毒性/AE 意图），安全 +X。
- AI 剂量模型（PK/PD 建模）：一期中精确显示本回合 DLT 概率，并降低它。
- AI 分子生成：发现期把一条指标直接调到目标区间中心。
- AI 患者分层（生物标志物）：二期中本场战斗的 PD 标记出现率降低。
- AI 入组匹配：推进 +大量。
- AI 数据治理：本局数据 +X，本场偏差概率降低。
- AI 竞品情报：战斗结束后揭示下一个竞品事件。
- AI 实验设计：本回合其他卡的费用 −1。

部分 AI 卡需要流程等级达到要求才会进入卡池，作为跨局解锁的回报。

### 9.3 牌库管理

- 起始牌库：每类各几张基础卡，加 1–2 张低档 AI 卡（让玩家第一局就看到 AI 不可靠的一面）。
- 获取：研究节点、战斗奖励、合作/融资节点。
- 删除与升级：平台建设节点、合作/融资节点。

## 10. 跨局积累

- 存档文件 `user://company.json`，保存公司数据、流程等级、已解锁卡、历史项目记录。
- 公司数据累计达到阈值时，流程等级自动提升（初值阈值：50 / 120 / 220 / 350 / 500），每级解锁若干 AI 卡和流程能力。
- 开局界面显示公司资产概况，以及上一局带来的收益。
- 平衡原则：公司积累让 AI 更早可用、更稳，但不能替代本局的数据积累和打法。

## 11. 扩展口子（P0 只留结构）

- "项目档案"：药物类型和适应症，带属性修正和数据迁移率。P0 只做一个默认档案。
- 难度递进：后续项目逐步提高竞品强度和门槛。

## 12. 留给开发者决定

- 所有标注"初值"的数值，以及平衡方法（建议扩展现有固定种子测试，做多种子胜率统计）。
- 战斗规则的代码组织（建议：一个战斗模式基类，五个子类分别实现，由 `battles.json` 的 `mode` 字段选择）。
- 地图生成算法的细节，以及地图连线的 UI 呈现方式。
- 具体卡牌、事件、竞品的内容清单和文案。
- P0 阶段 UI 的具体布局（以信息清楚为准，P1 再做视觉重构）。

## 13. 建议的实现顺序

1. 属性层改造：疗效更名、进度门槛、本局数据、卡牌效果词汇、卡牌改为只在战斗中使用。
2. 战斗框架：模式基类、意图系统；把现有战斗迁移为"临床前·毒理"模式。
3. 其余四种战斗模式及跨阶段联动。
4. AI 卡、有效数据、模型偏差、流程卡。
5. 分支地图与新节点类型。
6. 竞争格局与 Go/No-Go 里程碑。
7. 跨局存档与公司资产界面。

每一步完成后都应保持游戏可从开局玩到终局，并让回归测试通过。
